# 02. Stack

Rule #1: **the stack you debug fastest yourself.** AI writes the code, but fixing it and answering for decisions is on you.
Rule #2: **boring technologies.** A new library only if it saves > 30 minutes or is the de facto standard.

## launchpad base stack

| Layer | Choice | Why |
|---|---|---|
| Backend | Python 3.12+, **FastAPI**, Pydantic v2, uvicorn | Fast, types at the boundaries, OpenAPI out of the box |
| Packages | **uv** (lock file) | Fast reproducible install |
| Quality | ruff (lint + format), pytest | One tool per role |
| Metrics / logs | prometheus-client, JSON logs (stdlib) | Production feel without infrastructure |
| Frontend (if there is a UI) | **Vite + React + TypeScript**, Tailwind v4, **shadcn/ui** (radix, lucide), TanStack Query, zod | Best generated by agents; shadcn gives ready accessible components and a CSS-variable theme |
| Frontend quality | oxlint, prettier, vitest + Testing Library | Fast, almost no configuration |
| Run | Docker Compose, Makefile | One command on a clean machine |
| Storage | SQLite via stdlib `sqlite3` → Postgres when needed | No ORM while the schema is small |

### What to add and when (backend)

| Need | Use |
|---|---|
| DB | stdlib `sqlite3` + `schema.sql` (`CREATE TABLE IF NOT EXISTS`), file `DB_PATH=data/app.db`, `:memory:` in tests. One connection (`check_same_thread=False`) + `threading.Lock`, WAL. State transitions are compare-and-set (`UPDATE … WHERE step = ?`, check `rowcount`). SQLAlchemy + Alembic once there are > ~10 tables or Postgres is needed |
| Vector search / RAG | Postgres + pgvector |
| LLM | With `--llm` there is a task-level port (`Assistant`) with a rule-based mock and the `OpenAICompatLLM` transport (OpenAI, OpenRouter, vLLM, Ollama). A new LLM task is a new method or port in `domain/ports.py` that takes and returns domain types; the prompt and response parsing live in the adapter, the mock deterministically builds the answer from the input. Anthropic is a separate transport following the same scheme |
| Background jobs | FastAPI `BackgroundTasks`; a queue only if jobs take > 30 s or need reliability |
| ML / data | pandas / polars, scikit-learn |
| HTTP to external APIs | httpx with a timeout, behind a port in `adapters/` |

### Frontend

- Components: **shadcn/ui**. The base set is already in `src/components/ui/` (button, input, label, textarea, card, badge, alert, skeleton, separator). Need more: `npx shadcn@latest add <name>`; to find one: `npx shadcn@latest search <query>`, documentation: `npx shadcn@latest docs <name>`. Files in `components/ui/` are project code and can be edited, but prettier skips them so that `add --diff` shows only our changes.
- `cn` is the shadcn package [`cn`](https://github.com/shadcn-ui/cn) (a replacement for clsx + tailwind-merge), re-exported in `@/lib/utils`.
- Theme: CSS variables in `src/index.css` (`:root` and `.dark`), font `@fontsource-variable/geist`, icons `lucide-react`. Use only tokens for colors in components (`bg-primary`, `text-muted-foreground`), not `text-gray-500`.
- Animations: `motion`, when needed.
- Server state: TanStack Query, not hand-written `useEffect`.
- API responses are validated with zod (`src/api/client.ts`).
- Client types can be generated from OpenAPI (`openapi-typescript`) once there are more than five endpoints.

## Outside the base stack

If the idea requires something else (a mobile app, a pure Go service, Next.js fullstack, a CLI), **record it explicitly in `docs/decisions.md`** and adapt the skeleton. Launchpad currently generates only FastAPI (+ React).

## LLM providers

- Provider and model **only through ENV** (`LLM_PROVIDER`, `LLM_MODEL`, `LLM_BASE_URL`).
- `LLM_PROVIDER=mock` is the default: deterministic answers, works without keys.
- Structured output (JSON schema) wherever code parses the answer.
- PII is masked in domain before sending (`mask_pii`).

## Versions

Versions are pinned by the lock file (`uv.lock`, `package-lock.json`). Before using a library API, check current documentation via **context7**, not from memory.
