# 11. SEO, AI search and analytics

Goal: search engines and AI assistants (ChatGPT, Perplexity, Claude, AI Overviews) see and cite the pages, and we see where people come from. The foundation is in the skeleton; the project does not break it and extends it with content.

## What the skeleton already has

| What | Where | Why |
|---|---|---|
| Prerender | `frontend/src/entry-server.tsx`, `frontend/scripts/prerender.js` (step of `npm run build`) | GPTBot, ClaudeBot, PerplexityBot **do not execute JS**: without prerender an SPA is empty to them ([Vercel](https://vercel.com/blog/the-rise-of-the-ai-crawler)) |
| meta, Open Graph, JSON-LD | `frontend/index.html` | Title and description in results and link previews |
| `robots.txt`, `sitemap.xml`, canonical | generated by `prerender.js` from `SITE_URL` | Indexing only in prod |
| Analytics | Umami: `UMAMI_WEBSITE_ID` → script on every page | No cookies, so no consent banner needed |
| Legal pages | `frontend/src/legal/<lang>/*.md` → `/legal/<lang>/<name>/`, `<html lang>` by language | Written by `/legal` |

Build environment variables (in `render.yaml` on the web service):

| Variable | stage | prod |
|---|---|---|
| `SITE_URL` | stage URL | own domain |
| `ALLOW_INDEXING` | not set (stage is closed: `noindex`, `Disallow: /`) | `true` |
| `UMAMI_WEBSITE_ID` | optional, a separate site in Umami | site ID |

## Rules for page code

- Everything a bot must read is in the HTML after prerender: title, product description, key text. Check with `make audit`, the "text visible without JS" row.
- Components render without a browser: `window`, `localStorage`, `Date.now()` only in `useEffect` and handlers. Otherwise the build fails or React complains about a hydration mismatch.
- One `<h1>` per page, a meaningful `<title>` and `meta description` written for the user's query, not the project name.
- A new public page (segment landing, FAQ, article) gets its own path in `renderPages()` so it lands in prerender and the sitemap. Internal app screens behind login do not need prerender.
- Images with `width`/`height` and `alt`; fonts are already self-hosted via `@fontsource`.

## AI search (GEO)

- Answer the question directly in the first paragraph of the page; then add structure: question headings, lists, tables. This makes the text easier to cite.
- Facts with numbers and sources get cited more readily than generalities.
- `robots.txt`: do not block search bots (`OAI-SearchBot`, `ChatGPT-User`, `Claude-SearchBot`, `PerplexityBot`), otherwise we will not be cited. Training bots (`GPTBot`, `ClaudeBot`, `Google-Extended`) are a project decision; open by default.
- We do not make `llms.txt`: Ahrefs and SE Ranking studies found no effect, and Google does not support it.
- For more depth, use the `ai-seo` skill from [marketingskills](https://github.com/coreyhaines31/marketingskills) (arrives in the grow phase).

## Audit: `make audit`

```bash
make audit                          # stage
make audit URL=https://example.com  # any public URL
```

1. **PageSpeed Insights API**: the same numbers as on [pagespeed.web.dev](https://pagespeed.web.dev/): Performance / Accessibility / Best Practices / SEO scores, lab metrics and CrUX field data (p75 of real users; appears only with noticeable traffic).
2. **Bot view**: raw HTML without JS: text, title, description, lang, h1, canonical, OG, JSON-LD, robots.txt (whether it blocks AI search bots), sitemap. A failed required check gives exit code 1. On stage, ⚠️ on noindex, robots.txt and sitemap is normal: stage is closed to indexing on purpose.

Key: without it the shared Google quota almost always answers 429. Get one in [Google Cloud Console](https://developers.google.com/speed/docs/insights/v5/get-started) → an API key with access to the PageSpeed Insights API, and put it in the project's `.env` (it is in `.gitignore`) or in the shell profile as `PSI_API_KEY`.

Thresholds (Core Web Vitals, p75, [web.dev](https://web.dev/articles/defining-core-web-vitals-thresholds)): LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1. Lab substitute for INP: TBT ≤ 200 ms. SEO score 100, Accessibility ≥ 90.

Local Lighthouse (Chrome DevTools MCP, `lighthouse_audit`) is for quick iteration; a 10–15 point gap from PSI is normal, and PSI numbers go into the report.

## Analytics: Umami

1. **Human:** an account at [cloud.umami.is](https://cloud.umami.is) (a free plan exists) → *Add website* → domain → copy the Website ID.
2. **Human:** Render → web service → Environment → `UMAMI_WEBSITE_ID`, redeploy.
3. Events go as an attribute on an element, no code: `<Button data-umami-event="signup-click">`. A core scenario step = an event; this way the success signal from the brief is counted automatically.
4. Umami parses UTM tags (`?utm_source=...`) and referral parameters itself; always add them to links for growth channels.
5. The agent reads data through the [Umami API](https://umami.is/docs/api) with an API key (`UMAMI_API_KEY` in the shell profile).
